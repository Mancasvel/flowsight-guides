Turn work context into a clear client handoff

A handoff gives the next person enough information to continue. Use activity context to recover the work, then organize the final document around delivery state, access and decisions.

By Manuel Castillejo · 2026-10-11

In this guide
  • Name what is being handed over
  • Give usable access instructions
  • Make open decisions easy to find
  • Review what you send

Name what is being handed over

Describe the deliverable, version and scope. Say which parts are complete, reviewed, pending or excluded. A client should not need to reconstruct delivery state from the applications you used or the hours recorded.

Compare FlowSight's summary with actual files, issues and decisions. Correct any interpretation that turns work in progress into a finished outcome. Identify the evidence for each status and confirm that the client is authorized to access it.

Give usable access instructions

List locations and permissions needed to use the delivery. Describe the expected starting point and any prerequisite the recipient must arrange. Do not paste secrets into the handoff; use the agreed access process.

Verify links from the recipient's perspective where possible. An internal reference can appear complete while remaining inaccessible. If you cannot verify access, state the uncertainty and who can resolve it.

Make open decisions easy to find

Separate defects, pending validation and decisions requiring client input. Each item should identify its consequence, responsible person and next action. Avoid burying a blocking choice inside a long activity recap.

Use context only where it explains a relevant condition. Support requests, meetings or investigation may explain a schedule change, but correlation alone does not prove cause. Keep observations and interpretations distinct.

Review what you send

Remove internal conversations, unrelated project names and personal information the recipient does not need. Local analysis does not prevent exposure once a report is shared. Review any connected service that processes the handoff.

Open the final document and check version, recipient, status and next action. Arrange a review point for unresolved items. The handoff template is an editable writing resource; it does not imply automatic generation or import by FlowSight.
